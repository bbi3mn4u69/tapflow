# ADR-006: Browser cookies and encrypted Android refresh sessions

Status: accepted, 2026-11-08.

Use HS256 access JWTs with a private environment key of at least 32 bytes, issuer, audience, subject, issued/expiry times, UUID token ID and refresh-family/client claims. The lifetime is fixed at 900 seconds. Ktor verifies the algorithm/signature and claims; every authenticated request also checks the active user and a live refresh family in PostgreSQL. Membership and owner checks use current tenant-scoped SQL, with no administrator bypass.

Refresh tokens contain 256 random bits and only SHA-256 hashes are persisted. A refresh locks the user, re-reads its session and rotates within one transaction. Reusing a rotated token revokes the whole family; commit that revocation before returning 401. User locking also serializes logout and simultaneous rotations. Expiry is absolute at the original family's deadline (14 days by default), not extended by refresh. Logout invalidates family access immediately through the database check.

The browser receives a host-only HttpOnly, SameSite=Lax cookie scoped to `/api/v1/auth/web`; Secure is mandatory for deployed/HTTPS configurations. Only loopback HTTP development relaxes Secure. Cookie mutations require an exact allowed Origin (or Referer origin) and `X-TapFlow-CSRF: 1`; there is no permissive CORS policy. The SPA keeps access tokens in memory, deduplicates refresh, retries an unauthorized read once, and clears private query data on identity/membership changes and logout.

Android uses an AES-256-GCM key held in Android Keystore. Only authenticated ciphertext and its IV are saved in private preferences; corrupt/unreadable ciphertext signs out. Access tokens stay in memory. Backups remain disabled. A shared `packages/android-auth` Android library provides networking, encrypted storage and account UI for both apps; the NFC protocol module remains pure JVM. This avoids duplicate authentication/security implementations and adds no DI framework or HTTP dependency. Native requests use bounded platform HTTP connections, reject redirects and require HTTPS, with a debug-only exception for the emulator host `10.0.2.2`.

Login limits are 20 requests/IP and 5/account per 15 minutes; refresh/logout limits are 60/IP/minute. Pairing paths have 10/IP/minute and, after authentication, 10/user/minute. Optional registration is disabled by default and restricted to customer accounts, at 3/IP/hour when enabled. Buckets are bounded and process-local; shared rate limits and explicit trusted-proxy handling are required before scaling/deploying behind a proxy. Client-supplied forwarding headers are not trusted. Bodies are limited to 16 KiB, and all API responses use `Cache-Control: no-store`.

Pin Lifecycle 2.11.0, coroutines 1.11.0 and React Router 8.5.1. Use the existing Ktor 3.6.1 authentication/body-limit artifacts and its java-jwt 4.6.0 dependency; avoid a separate JWT implementation.
